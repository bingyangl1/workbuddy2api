## 三、必须吸收的 1 项（有上游实证 + 我们同样的 bug）

### X-Conversation-ID 恒发（上游 #36）

**上游实证**（逐账号直连测）：

> 只要头在场（固定字符串即可，**不校验会话存在性**）即全部通过，与账号无关 ——
> 是**请求维度**不是账号维度（此前易被 displayTips 误导为「账号被封」）。
>
> 缺头 → `400 code=11-128 "conversation id missing"`
> → displayTips：「这次调用没通过渠道校验，可能不是官方客户端发出的」

**我们同样的 bug**（`admin/routers/proxy.py:479-482`）：

```python
conv_id = pool.extract_session_key(body)
if conv_id:
    # 透传客户端原值优先；客户端没给就不伪造（避免误导上游建错会话）
    h["X-Conversation-ID"] = conv_id        # ← 客户端没给就完全不发
```

**上游的修法比补丁说明更精细**（值得照抄的关键细节）：

| 字段 | 用途 | 缺省时 |
|---|---|---|
| `ConversationID` | body 提取的**客户端原值**；**也是 `prompt_cache_key` 会话段的哈希源** | 保持空（**不覆盖**） |
| `ConversationHeaderID` | **仅用于出站头**的兜底值 | = `ConversationRequestID`（轮级聚合键） |
| 出站 `X-Conversation-ID` | 客户端原值优先，缺省用兜底值 | **恒发** |

**为什么分两层（上游注释原话）**：

> 只写 ConversationHeaderID 而不覆盖 ConversationID：后者仍是 prompt_cache_key
> 会话段的哈希源，**保持无会话键客户端的「每账号恒键」前缀缓存命中率不被打碎**。

即：兜底值如果用轮级键，会**逐轮变化** → 若写进缓存键则前缀缓存全失效。
所以兜底值**只进出站头**。
