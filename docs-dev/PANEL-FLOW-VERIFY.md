## realm 隔离验证（干净 profile）

| 操作 | `localStorage['wb.realm']` | 模型数 | 判定 |
|---|---|---|---|
| 首次打开模型页 | `None`（用默认 cn） | **31 个** | ✅ 国内版 |
| 点「国际版」 | `global` | **18 个** | ✅ 国际版 |
| 切回「国内版」 | `cn` | **31 个** | ✅ 回到国内版 |

**31 / 18 精确对应两版真实数量**，且能来回切换。

### 一个容易误判的点

realm 存在 `localStorage['wb.realm']` 且**跨会话保留**（记住用户选择，这是设计）。

我第一轮测试就栽在这里：上一轮点了「国际版」，下一轮打开页面时
`useState('cn')` 的默认值被 `useEffect` 里的 `localStorage` 覆盖，
导致「默认打开」看到的其实是上次选的版本 —— 一度误以为修复没生效。

**排查方法**：用干净 profile + 显式打印 `localStorage` 与按钮选中态。

## 国际版模型同步实测

### 修复前的状态

```
realm=cn      31 个
realm=global   0 个   ← 从没同步过
```

用户看到的「切国际版仍显示国内模型」直接原因是：
**不传 realm 时返回全部 31 个（全是 cn 的）**。

### 执行一次真实同步（单次、低频）

```
POST /api/models/sync?realm=global
→ {"realm":"global", "source_account_id":13,
   "total_fetched":18, "added":18, "updated":0,
   "total_in_db":49, "enabled":49}
耗时 3.6 秒
```

`source_account_id: 13` 正是那个国际版账号 —— 走的是国际版上游。**同步是好的**。

### 同步后

```
realm=cn      31 个  （不变）
realm=global  18 个  ✅
```

## 模型中心的定位（回答「为什么不能启停」）

源码注释写得很明确：

> 本页管「这个模型是什么」—— 显示名 / 描述 / 上下文 / 最大输出 /
> 推理档位 / 能力标记 / 积分倍率
>
> 倍率/启停是本地 ModelConfig 合并进来的 —— **本页只读，启停管理仍在「模型」页**。

| 页面 | 职责 |
|---|---|
| **模型管理**（`/panel/models`） | 白名单启停（有开关 + 批量启用/禁用）+ 倍率 |
| **模型中心**（`/panel/models/catalog`） | 只读浏览：这个模型有多强、支持什么 |

实际截图显示模型中心信息很丰富：按系列分组（其他 / Auto / DeepSeek / GLM）、
上下文长度（1000K / 256K）、最大输出（128K / 32K）、
推理档位（low / medium / high / xhigh / max）、积分倍率（x0.08 credits）、
能力标记（看图/工具/思考）—— 这些是**决定要不要启用某个模型**的依据。

## 旧面板的 realm 情况（补充说明）

`dev.ps1 -Live` **只关闭上游只读护栏**，不切面板（切面板用 `-NextPanel`）。

旧面板（`admin/static/index.html`）**完全没有 realm 概念**：

* `grep realm` → **0 处**
* 3 处调 `/api/models/configs` **都不传 realm**

本次修复让后端「不传时仍返回全部」（兼容旧调用），所以旧面板行为不变
（继续显示混合清单，因为它本身没有版本切换 UI）。

> 旧面板不再投入新功能是既定方向。要在旧面板做版本隔离，
> 需先给它加 realm 切换器 —— 那是另一块工作量。
